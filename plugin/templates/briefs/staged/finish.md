## What you do, in order

1. `ledger build db --report --db wip/<task>/check.db` (never the shared notes.db): 0 errors for your note; fix what it reports in the note, with the Edit tool or Python.
2. `ledger analyse onboard <note> --db wip/<task>/check.db --out wip/<task>/onboard.md`.
3. `ledger extract fill --note <note> --sources <held dir> --onboard wip/<task>/onboard.md` (the metadata keys, the inventory, the audit counts line, the cross-check candidates between the markers); then the Cross-checks: every candidate in onboard.md READ on both sides (this note's row in the note; the other note's row in its own note, found by `ledger analyse rows` or by the Read tool on the cited line), kinds answers / corroborates / contradicts / extends / fills / chain, independence judged (a same-speaker repeat or a relay of its own source is `extends`), `point:` and the `[div: ...]` tag with `party=` on every contradicts row, the custody line on every row; the kept candidates written to `wip/<task>/xc-accept.md` (`<id> <kind> <verdict> | <note>`) and applied with `--accept`; rejected candidates not listed; chain findings as rows of Kind `chain`. Every `answers` row you are confident of goes to `answered_questions` in the report in tools/integrate_report.py's shape; `chain_leads` for every chain finding and open thread.
4. `ledger extract fill --check <note> --sources <held dir> --report wip/<task>/report.json`: no DIFF (a DIFF the tool causes itself is reported in `notes`, not hidden).
5. `ledger build db --report --db wip/<task>/check.db` again; `ledger prepare skeleton --check <note> --form <form>` passes; `ledger extract verbatim <note>` as its own call; `ledger analyse echoes --help` and the echo check with check.db where the standing brief asks for it; `ledger extract gate --note <note> --wip wip/<task>` passes.
6. `tracker_rows` in report.json is the list of tie rows or is left out; a count goes under `tracker_rows_in_note` (a count under `tracker_rows` stops the integrate step). No `<!-- fill -->` marker is left anywhere in the note (`ledger extract fill --check` in step 4 names them; report-check fails a report whose note keeps one). `Status` in the metadata: remove the in-progress key (or set it as the form's exemplar does); `report.json` complete: every key of intake-standing.md's base keys and the form brief's keys (`source_kind`, `earliest_telling_search`, `roots_added`, `first_telling_rows`, `file`, `subject_rows`, `register_new`, `register_updates`, `relations`, `chain_leads`, `answered_questions`, `timeline_rows`, `claims_rows`, `audit_counts`, `cited_sources_not_held`, `narrative_rows_addressed`, `blocked_passages`, `notes`, and for a recording the video form's keys), the pack's keys ({{pack.report_keys.document}}; for a recording {{pack.report_keys.video}}), with the writer's values kept where you did not change them; `ledger extract report-check wip/<task>/report.json --form intake-document --pre-sample` (or `intake-video`) passes.
7. progress.md's last line is `finish phase complete`. Reply with the report JSON (the contents of report.json, nothing else).
