# Phase briefs of the staged intake (core template, platform phase 4, 2026-10-22; from wip/intake-staged/phases/README.md of 2026-10-16; tools/intake-staged.md)

Templates, rendered by the skill into `wip/<run>/briefs/staged/`, whose path the orchestrator passes to `tools/workflows/staged-intake.js` as `phasesDir`; the file names read.md, write.md and finish.md are the ones the workflow opens. Slots used across the three: `{{pack.model_policy}}` (README), and in each phase brief the slots its own table lists.

An intake is split into short-lived agents with small contexts, run by `tools/workflows/staged-intake.js`: read (every unit, findings per unit) -> gate 1 (script) -> write A (the ledger: metadata, claims ledger, audit, from the findings alone) -> gate 2 (script) -> write B (the sections, from the findings and the finished ledger) -> gate 2 -> finish (checks, cross-checks, report) -> gate 2 again. This is the default intake path; the single-agent intake (intake-document.md, "Two paths") is the named alternative. The standing briefs still bind every phase: intake-standing.md (the standing rules, the pre-pass files, checkpoint, blocked output, the base report keys), the form brief (intake-document.md for a document or text; intake-video.md for a recording), intake-adverse.md (adverse sources), the run brief named in `wip/<task>/TASK.md`, operations.md, tools/schema.md with the pack's schema extensions, tools/agent-wip.md, tools/filter-blocks.md. A phase brief says only which part of the work is that agent's, what it reads, what it writes, and what it hands the next phase. Nothing is omitted to save tokens: every unit is read in full, every row and quotation is as accurate as the single-agent form made them; the split only stops each agent carrying what the next one needs in a file instead of in its context. The findings are a digest, not a copy (the compact form, 2026-10-23, wip/compact-findings/): the reader writes pointers and key words, the writer pulls the source's words by pointer with `ledger quote`, so the source reaches the writer once, span by span, and not again through the findings. The write is split (2026-10-23, wip/compact-findings/REPORT.md section 5: a writer's cost is its standing reading times its calls, not the findings): writer A writes the ledger and the audit, writer B the rest from the finished ledger, each reading the schema and the briefs by section and only the sections its part needs, in parts of about 3,000 words. {{pack.model_policy}}

What the orchestrator does before launch (tools/intake-staged.md section 2): `ledger prepare chunk` (units and manifest), `ledger prepare skeleton` (skeleton.md), `ledger prepare context` (context.md), `ledger prepare timeline-prepass` (timeline-candidates.md), `ledger brief render` (the rendered briefs of the run), `wip/<task>/TASK.md` (the source, the note path, the form, the label, the subjects, the run brief, the held threads), `wip/<task>/prompt.md` (tools/agent-wip.md item 0); then keep-awake (tools/agent-wip.md item 9: request keep-awake before launch and hold it until the run's last agent has replied: in the Claude desktop app its keep-awake tool (request_keep_awake, until the session is idle); elsewhere the system's own (macOS `caffeinate -i`, Linux `systemd-inhibit`, Windows the power plan or `powercfg /requestsoverride`). A sleeping computer kills the agent in flight (2026-10-24: a writer died mid-response and the guard's resume cost 4.8M records); a closed lid still sleeps); then the workflow with each task's unit and word counts from the manifest.

WIP, resume and blocked output (standing, every phase): `progress.md` in `wip/<task>/` from the first minute with the step reached and the next step; every output file saved as you go; on any resume read your wip folder first and continue from the last completed step, never from scratch. Before every large output copy the unit in hand to `wip/<task>/current-unit.md` by the copy operation of operations.md (the reader: the unit file `wip/<task>/units/NNN.txt`; the writer: the findings file being rowed; the finisher: the onboard report) and name it in progress.md. The blocked-output paragraph of intake-standing.md binds every phase; the script catches a death (tools/filter-blocks.md section 6) and resumes you from your wip folder.
