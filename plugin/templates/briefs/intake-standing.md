Template. The skill renders it with the active pack's slot values (`ledger brief render`, wip/platform-phase4/skills.md) into `wip/<run>/briefs/intake-standing.md`; an agent reads only the rendered copy. Merged from the live briefs wip/intake-1008/COMMON.md, wip/intake-1008/brief-document.md and .next.md, and wip/<video-run>/brief-video.md and .next.md: the rules those briefs repeated, once. The form brief (intake-document.md or intake-video.md), the adverse addendum (intake-adverse.md) when the source is adverse, the run brief that TASK.md names, and operations.md are read with it.

## The project and the boundary

Project {{ledger.root}} ({{ledger.title}}). Markdown is canonical; notes.db is derived. Never init git. Do not run the database or index build on the shared notes.db; validate with `ledger build db --report --db wip/<task>/check.db` (0 errors for your note). Edit nothing outside your own note and your wip folder; everything that should change elsewhere goes in the reply JSON. Read tools/schema.md completely first (v1.3, sections 1 to 11; section 2's attribution rulings and hop chains on every non-firsthand claim; section 10's cross-check kinds, the divergence rule and the tag `[div: dir=…; core=…; stab=…; indep=…; timing=…; path=…; party=<name>]`, the split rule; section 11's permanent decimal timeline IDs), with the pack's clauses to it ({{pack.schema_extensions}}). No word cap. Government offices are never taken at face value; an office contradicting a witness is a lead, never a correction to the witness (the agency rule, tools/schema.md section 10). {{pack.model_policy}}

Every file operation in the forms of operations.md (loaded with this brief): `ledger` or Python or the harness's Read, Write, Edit and Grep tools; no shell idiom.

## Standing rules (one line each; the memory rules of the project)

- Intake policy (owner 2026-10-14, tools/intake-policy.md): search for the claim's earliest public telling and record it (`earliest_telling_search` in the report; `[first telling: FU-n]` tags on rows dated earlier than a held telling, FU-n from research/first-utterance-register.md, whose tests are dated against the pack's catalysts ({{pack.catalysts}}), and the report's `first_telling_rows` list as tools/intake-policy.md rule 1 shapes it); bring in the agency document a telling rests on; a relay of a held root enters only as an earliest telling or a divergence (`roots_added` in the report); a leaked document is hearsay with the leaker as root until an agency release matches it; the report's `source_kind` names the note's kind (compiler, host, witness, document, adverse, earliest-telling).
- Chain of custody on every non-firsthand row: `attribution:` and `chain:` in the Note cell, classes per schema section 2 (a document's issuing office is the speaker of its own rows; a document that asserts a record exists without naming it is `read` with `document claimed, not named`; on a recording, a host's own experience is `firsthand` with the host in Speaker, unsourced synthesis is `host`, "I was told", "sources say", "people I know inside" is `hearsay` with the teller described, a named book, study or document is `read`).
- Forthrightness audit (section 3) for every note under the audited subjects ({{pack.audited_subjects}}), including documents. Interview form for recordings: every party who asks and answers, reverse questions marked, stated declines, pseudo-declines, the Audit counts line and one explanatory line. Document form for texts: what the author states, hedges, omits, caveats, who supplies the frame, what a reader would not learn; the monologue mapping, stated under the counts line; redactions are walls (a redaction is a closure by the releasing office, Basis `redacted: <exemption cited>`), and a document's silences on a question the ledger holds are recorded in "what is withheld". The pack's channelled-class clause binds where the source is of that class ({{pack.channelled_clause}}). The section's heading is `## Forthrightness audit`, as the skeleton emits it.
- Object watch (section 6): every object, material or artifact, in any source, logged in the section 6 table against the pack's object register: {{pack.reference_objects}}
- Actor and polity register: {{pack.actor_register}}
- Relations: return every who-knows-whom, employer, funder, member-of, directs, source-of edge the source shows (the register's columns: a, b, kind, hierarchy, when, what, source, chain, confidence); check `ledger analyse relations "<name>"` first and return only what the register lacks or dates better. Independence: name who hosts, who relays, who was in the room; every relation row and cross-check Note states the chain so a retelling is never counted as independent.
- Dated timeline (section 11): every dated event, permanent decimal IDs, Sortable, Agreement against the database (matches, drifts, contradicts, new), ruled from `wip/<task>/timeline-candidates.md`, with the `[div: ...]` tags on contradicts and drifts rows as the schema describes; the orchestrator places rows in the consolidated era pages afterwards ({{pack.eras}}).
- Divergence rule: where this source tells a story the ledger holds differently, record the divergence with the party named; an agency's or office's contradiction of a witness is a lead, never a correction (the agency rule); the witness's row stands and the office's row stands beside it.
- Echoes: same wording or the same rare detail as a held telling is noted (research/echo-patterns.md; `ledger analyse echoes --help`, with your check.db); the stop-list is tools/stock_phrases.txt with the pack's domain list ({{pack.stock_phrases}}): the same rare detail across unlinked mouths is corroboration, the same wording across linked mouths is an echo.
- Speaker ledgers: {{pack.speaker_ledgers}}
- Forthrightness chart data: {{pack.forthrightness_charts}}
- Canon and codebook (the canon layer, tools/platform-plan.md): a row that quotes or relies on a canon text ({{pack.canon}}) cites the text and its unit; a reading by a code of the pack's codebook ({{pack.codebook}}) is a lead naming its code, never a finding.
- Leads: `chain_leads` in the lead-register shape (lead, kind, sources, settles), with a test and a status, for every open thread the source raises or bears on; cite the existing lead numbers it answers in `answered_questions` (the shape in tools/integrate_report.py's docstring).
- Cross-checks (section 10) are written last, after `ledger build db --report --db wip/<task>/check.db` and `ledger analyse onboard <note> --db wip/<task>/check.db --out wip/<task>/onboard.md`; every candidate is read on both sides; every row names the note and row it checks; kinds answers / corroborates / contradicts / extends / fills / chain, independence judged (a same-speaker repeat or a relay of its own source is `extends`, never `corroborates`), tags on every contradicts row with `party=`.
- Held rows: find the held row for a fact with `ledger analyse rows "<query>" [--note <stem glob>] [--table claims|timeline|audit] [--json]` (full-text search over claims, timeline, audit, quotes and people rows; returns citations `[<stem> claims N]`, `[<stem> tl N]`, `[<stem> audit N]` with the cells; tools/rows_search.md) before reading a note; `ledger narrate narratives --rows <file>` then prints known references in batch.
- Third-party texts and copyright: the held copy is the source; quote in short passages only, as the schema allows; the note links the held copy's path and the original URL; never reproduce a copyrighted text at length. Web access: you may fetch a public page to check a fact, label it `own: Claude, web, <confidence>`, quote at most a sentence or two of a copyrighted page, never archive one; never fetch from a video platform (the transcript and description are already held; if the description is missing, say so).
- Openness is not truth; a wall is a boundary, not a denial. Hints (omissions, speaking around, offhand remarks) are noted as signals in the audit prose, never promoted to claims.
- Writing: in parts of about 1,500 words (claims in units of 20 rows), written to `wip/<task>/parts/` as drafted, with the Write tool or Python; the verbatim check on each part as its own call after the part is written, never chained to the write (`ledger extract verbatim <part>`; operations.md); before each large write copy the unit in hand to `wip/<task>/current-unit.md` by the copy operation and name it in progress.md; findings per unit before the next unit is read.

## The pre-pass files and the generated parts (the default path)

The orchestrator prepares these before any agent starts (wip/platform-phase4/skills.md, /intake); the agent works from them.

- **Units** (tools/chunk_source.md): `ledger prepare chunk <held source> --wip wip/<task>` cut the source into `wip/<task>/units/NNN.txt` with `units/manifest.md` listing every unit with its source file, span (pages, timestamps, post title and date, or line range) and word count; each unit opens with one header line carrying the same, so a citation can be written from the unit alone. Read the units in manifest order; never re-split. Mark by command, `ledger prepare chunk --wip wip/<task> --mark NNN read` (then `"findings written"` once the unit's findings are written, `rowed` once its rows are in the note); on a resume `ledger prepare chunk --wip wip/<task> --status` names the first unit without findings, and you continue from there. Before each large output, the copy operation from `wip/<task>/units/NNN.txt` to `wip/<task>/current-unit.md` and one line in progress.md naming the unit number and where its output goes.
- **Skeleton** (tools/note_skeleton.md): `ledger prepare skeleton --form <form> --task wip/<task> --note <note> --source <held path>` wrote `wip/<task>/skeleton.md`: the metadata block in schema order with the derivable cells filled, every section heading in the form's order, every table's header row, and two example rows per table lifted verbatim from the pack's exemplars, each marked `<!-- example row, delete -->`. Work from it. Do not read the exemplars in full; read an exemplar only for a section whose form the skeleton leaves unclear, by section (the skeleton's comment under each heading gives the exemplar's line range; read that range with the Read tool). Copy their forms; do not invent new section shapes. Before you finish, `ledger prepare skeleton --check <note> --form <form>` must pass.
- **Context pack** (tools/context_pack.md): `ledger prepare context <source files> --wip wip/<task>` wrote `wip/<task>/context.md`: held rows by name, date, identifier and URL, register clusters, narrative ledger rows, leads. Read it before any held note; open a note only for a row it cites. A term match is never a finding.
- **Timeline candidates** (tools/timeline_prepass.md): `ledger prepare timeline-prepass wip/<task>/units --wip wip/<task>` wrote `wip/<task>/timeline-candidates.md`; rule the Dated timeline's Agreement column from it, and search beyond it only for a date it marks as having no held row.
- **Generated parts** (tools/note_fill.md): the derivable metadata keys, the document inventory, the audit counts line and the cross-check table are generated: `ledger extract fill --note <note> --sources <held dir> --onboard wip/<task>/onboard.md` after the audit table and the onboard check, and `--check` before the report check; type none of these by hand. An `--accept wip/<task>/xc-accept.md` file, one line per kept candidate `<id> <kind> <verdict> | <note>`, writes only the candidates you kept after reading both sides.

## Checkpoint (standing rule, tools/agent-wip.md)

From your first minute keep `wip/<task>/progress.md` (done, next, files touched); write the note section by section with `Status: in progress` in its Metadata until finished; keep parts in `wip/<task>/parts/` and findings in `wip/<task>/parts/findings.md` (single-agent path) or `wip/<task>/findings/NNN.md` (staged path); build `wip/<task>/report.json` incrementally and save the final JSON there before replying. Do not delete the folder. On a resume, read the wip folder first and continue from the last completed step, never from scratch.

## Blocked output (standing rule, tools/filter-blocks.md section 5)

> **Blocked output (standing rule, tools/filter-blocks.md).** If an output is refused or an extraction fails on a passage twice, do not retry a third time and do not paraphrase around the filter. Bisect the unit until the smallest failing piece is found, recording each attempt in `wip/<task>/bisect-<unit>.md`; write `wip/<task>/blocked/<n>.md` with the source location (file, lines or h:mm:ss, page), where in the deliverable it belongs, and one neutral sentence on what it is about (not the text); enter a pointer row at that place in the deliverable with the marker `[BLOCKED: see <source location>; wip/<task>/blocked/<n>.md; awaiting human summary]` (speaker, time and topic filled; Move n/a; `attribution: n/a (pointer); chain: 1: <speaker> (n/a)`, Source class `host`, the Note cell "An API output filter blocked every attempt to catalogue this passage on <date>; the owner has the source" ({{pack.blocked_precedent}})); note it in progress.md; list it in the reply JSON under `blocked_passages` (`[{"id","source","deliverable_location","about","bisect_file","attempts"}]`); and finish everything else. The owner will read the source, write a summary, and the orchestrator will splice it in under the owner's name; your work resumes from there. Prevention: never pass a fetched text through your own output (copy files by the copy operation); before each large output copy the unit's source material to `wip/<task>/current-unit.md` and name it in progress.md; write note parts of about 1,500 words and run the verbatim check on each as its own call; record findings per source as you read.
