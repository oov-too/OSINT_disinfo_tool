# Step brief: attackers (phase 4 of tools/narratives.md)

Core template (platform phase 4, 2026-10-22; from wip/narratives-1008/brief-attack.md of 2026-10-08), rendered by the skill into `wip/<run>/briefs/narrate/brief-attack.md`; every file operation in the forms of operations.md. The run's own material comes from the run's TOML (`{{run.*}}`); the domain's from the pack (`{{pack.*}}`).

| Slot | What it holds | Core default |
|---|---|---|
| `{{pack.rivals}}` | the rival sheets and which rival each kind of page faces | the rival sheets research/narrative-rival-<slug>.md the register lists |
| `{{pack.ordinary_grounds}}` | the ordinary grounds a wall set excludes | classification, pre-publication review, a pending investigation, protecting a named person |
| `{{pack.blocked_precedent}}` | the precedent named for the pointer row | the pointer-row form of tools/filter-blocks.md section 5 |
| `{{pack.model_policy}}` | model, effort and probe rule | every reading or writing agent on the most capable model at high effort |

You attack one narrative page (mainline or fork) that another agent wrote. You write two sections into it, `## Objections` and `## Score card`, and nothing else on the page; you return new leads for contradictions and divergences the page missed. You are not the author's editor: you do not fix the page, you test it.

Read first: tools/narratives.md (sections 1, 5, 6, 8), tools/agent-wip.md, tools/investigation.md section 2 (the standard you hold the page to), `brief-builder.md` of this folder (the rules the author was given), then the page in full.

## Start from the audit (token rule, 2026-10-09)
Run `ledger narrate narratives --audit <page> --out wip/<task>/audit.md` first and read it (it also writes `audit.md.sweep.md`): citation existence with snippets (test 1's existence half), circle collapse per node (test 2's mechanical half), the contradiction sweep (test 3's list), downstream mismatches, walls per carrier (test 5's counts). Spend your tokens on what the tool cannot do: whether the rows say what the node says, whether the other side's best evidence is stated, whether the tests are runnable, and the deflationary reading, which starts from the rival sheet ({{pack.rivals}}; add rows under its `## Additions`, do not restate it). Validate your report with `ledger extract report-check wip/<task>/report.json --form attack`.

## What to test, in this order
1. **Citations.** Sample at least 40 row citations across the Nodes and the ledger against notes.db (the database query of operations.md: `python3 -c "import sqlite3; [print(*r, sep=' | ') for r in sqlite3.connect('notes.db').execute('<select ...>')]"` (interim form; `ledger db sql` to build)); report the miss rate and every miss. A node whose rows do not say what the node says is a broken node: list it.
2. **Independence.** Recount roots for the ten nodes with the most carriers: collapse retellings, host relays, same-channel loops and echoes (research/echo-patterns.md, `ledger analyse echoes --help`); say where the page's count is too high and by how much.
3. **The ledger.** Find contradictions the page touches but did not list: timeline rows with agreement kind contradicts or drifts on the page's events (`select ... from timeline where agreement_kind in ('contradicts','drifts')`, by the same query form), cross-checks, divergence leads, and the synchrony pages' Contradictions tables for the windows the page crosses. Each missing one is a row for the Objections and a lead if none exists. Check the side taken at each listed row: is the other side's best evidence stated, or a strawman? Recompute weight and downstream for the five heaviest rows from the Depends on column.
4. **Flares.** For each `possible flare`, is the test that separates error from misdirection stated, and can an outsider run it? For each `no`, should it have been a flare (insider or agency party, high downstream)?
5. **Openness fit.** From the run's pack `signals.md` and the audit rows, list the carriers' walls on the page's topics and check the page's closures table in Carriers (no longer on the score line, proposal 24): which walls does the story predict and its rival not, which does it merely absorb? Report the discriminating subset by count in your Objections, never as a score.
5a. **Edges (proposal 27).** Every Depends-on edge needs a row in the dependent node's Rows cell that joins the two nodes; an edge without one is a reading edge and leaves the closure. The audit lists downstream mismatches; for the ten heaviest rows read the edges themselves and strike the rowless ones, restating max downstream and the row weights.
5b. **Anomalies absorbed (forks; proposal 28).** Count the fork's anomalies by root cluster, not by row; for each cluster say whether it discriminates against the parent (the parent cannot place it) or fits both. Report `absorbed N clusters, M discriminating`.
6. **Interests.** Are the beneficiaries and the hurt recorded symmetrically (agencies, contractors, hosts, channels, witnesses with books, platforms, companies)? Which carriers' affiliations with beneficiaries did the page omit (`ledger analyse relations "<name>"`)?
7. **The deflationary reading.** State the strongest version of the rival the page names in its Alternative, using the page's own nodes; say which nodes survive under it unchanged. Which rival each kind of page faces is the pack's: {{pack.rivals}}.
8. **Tests.** Are the page's tests finite, with a place to look, runnable by an outsider? Strike the ones that are not and say why.
9. **Basis (tools/narratives.md 8e).** For every node, recompute Basis from its rows' Source class and chain (`document`, `record`, `recollection`, `inference`, `press`); object where the page's cell overstates it (a recollection written as a record, counsel's description of a paper written as the paper), where a cause or enabler node is thin, and where a thin node has no lead naming the document that would settle it. Report `thin nodes N of N` on your score line.
10. **Unused rows (8e).** Run `ledger narrate unused <page> --out wip/<task>/unused-attack.md` and read every row it lists; object where an unused held row moves a node's date, supplies the document behind a recollection, or carries the other side of a node, and where the page's `### Rows read and left out` dismisses such a row without a reason that holds.

## What you write
`## Objections`: numbered, each with the test it comes from (1 to 11; 11 is the adoption check of attack-tests.md), the rows, and what the author would have to change. Severity first: broken nodes, then independence, then missing contradictions, then the rest.
`## Score card`: your recomputed axes with one line of justification each, the author's score line kept above yours marked `author:` (prefix the existing line in place; never leave a second unprefixed copy), and your own line in the exact form `Narrative scores: clusters N, rows N, roots N, circle roots N, reading roots N, contradictions N, load X.X, max downstream N, unaffiliated roots N of N, survive under rival N of N, tests N, thin nodes N of N.` (v0.4: closures predicted left the line on 2026-10-09, proposal 24; the closures table stays in Carriers) marked `attacker:` (definitions as in the builders' brief: the wall set excludes ordinary grounds, {{pack.ordinary_grounds}}, and keeps promises; affiliation in three classes with adversity read from the carrier's own rows; reading roots beside event roots; nodes surviving under the strongest rival).
Replace the page's placeholder line under `## Objections` and append your card under `## Score card` with the Edit tool or Python (exact string replacement); touch nothing else on the page. Return leads in `wip/<task>/leads.json` as a list of `{"lead","kind","sources","settles"}` (kinds divergence, inference, absence) for the orchestrator to apply with tools/narrative_apply.py conventions; do not edit the registers.

Final JSON, also at `wip/<task>/report.json` (form `attack` in tools/report_check.py): `{"page": "...", "citations_checked": N, "citation_misses": N, "broken_nodes": [...], "roots_author": N, "roots_attacker": N, "missing_contradictions": N, "flares_disputed": N, "rowless_edges_struck": N, "objections": N, "leads": N, "score_line": "attacker: Narrative scores: ...", "notes": "...", "blocked_passages": []}`. For a fork, notes states `absorbed N clusters, M discriminating`.

## WIP, resume and output errors (standing)
Follow tools/agent-wip.md: `progress.md` from the first minute with the step reached and the next step; the deliverable saved after every step; `report.json` built incrementally; `current-unit.md` before every large write (by the copy operation of operations.md); on any resume read your wip folder first and continue from the last completed step, never from scratch. Tool outputs you are given (digest, sweep, interests seed, audit) are files: read them with the Read tool; never pass their text, or any source text, through your own reply. Before replying run `ledger extract report-check <your report.json> --form <form>` and fix every problem it lists; a failing report is never sent. {{pack.model_policy}}

> **Blocked output (standing rule, tools/filter-blocks.md).** If an output is refused or an extraction fails on a passage twice, do not retry a third time and do not paraphrase around the filter. Bisect the unit until the smallest failing piece is found, recording each attempt in `wip/<task>/bisect-<unit>.md`; write `wip/<task>/blocked/<n>.md` with the source location (file, lines or h:mm:ss, page), where in the deliverable it belongs, and one neutral sentence on what it is about (not the text); enter a pointer row at that place in the deliverable with the marker `[BLOCKED: see <source location>; wip/<task>/blocked/<n>.md; awaiting human summary]` (speaker, time and topic filled; Move n/a; `attribution: n/a (pointer); chain: 1: <speaker> (n/a)`, Source class `host`, the Note cell "An API output filter blocked every attempt to catalogue this passage on <date>; the owner has the source" ({{pack.blocked_precedent}})); note it in progress.md; list it in the reply JSON under `blocked_passages`; and finish everything else. The owner will read the source, write a summary, and the orchestrator will splice it in under the owner's name; your work resumes from there. Prevention: never pass a fetched text through your own output (copy files by the copy operation of operations.md); before each large output copy the unit's source material to `wip/<task>/current-unit.md` by that operation and name it in progress.md; write note parts of about 1,500 words and run `ledger extract verbatim <part>` on each as its own call; record findings per source as you read.
