# packs/pilot/lenses

Lens instances of the pilot pack. The lens form (the technique catalogue, the weighting rules, the database tests) is core, in tools/technique-catalogue.json; an instance supplies its techniques, their attribution, the mapping onto the catalogue, the parameters, the qualifications, the placements and its public-record checks.

| Instance | File | Source | Kind |
|---|---|---|---|
| The SFO lens | sfo-cooperation.json | the Serious Fraud Office's corporate guidance on self-reporting and co-operation (GOV.UK, OGL v3), held at sources/pilot/web/2025-04-24-sfo-cooperation-guidance/ | a lens from a text (setup stage 6) |

Counts: 15 techniques (S1 to S15: 8 technique, 6 operative, 1 exculpatory), each with the held line it rests on; mapped onto the catalogue: C1, C3, C6, C8, C10, C22 (close or partial); no counterpart in this text: C2, C4, C5, C7, C9, C11, C13 to C19, C21; new core criteria proposed: 8 (jurisdiction arbitrage, shielding individuals, tactical delay, flooding, non-preservation, the lawful-privilege exculpation, third-party custody; and S3's qualification). Placements: none (the text names no one; the rule for readers' placements is in the file). Public-record checks: K1 to K4, not run.

Why a text and not a person: the plan's lens rulings allow either (owner, 2026-10-22: "a manual, doctrine, playbook or treatise"); the project's first lens instance is a person's frame, so the pilot tests the other branch. The terms of reference were the fallback named in the brief: they define the question but state no technique, so they serve as the question source instead (pack.toml [question]).
