# ledger.acquire: the acquire layer (phase 3 of tools/platform-plan.md, 2026-10-22)

Adapters that fetch an item, hold it byte-for-byte, write its README and return a manifest row, all in the one form of [tools/hold-schema.md](../../hold-schema.md). The shared part is `base.py` (Record, HeldFile, Capture, Adapter.hold, the README generator, the rate gate, the manifest); each adapter adds only its `fetch`. Every adapter runs as a module or a script (`python3 tools/ledger/acquire/<adapter>.py ...`) and is importable as `from ledger.acquire import <adapter>` with tools/ on the path.

The browser-pane route of the plan's phase 3 is `web.WebAdapter.hold_bytes(url, data, tool=...)`: the pane fetches a page the site refuses to plain requests (some government sites do) and saves it; the adapter holds the saved bytes with the pane named as the capture tool.

## The fetching policy (the owner's, 2026-10-22)

The web adapter (and everything that fetches through it: document.fetch_url and fetch_page, published.py) sends an honest user agent, `LedgerAcquire/<version> (research ledger; <project title>; operated through Claude-User; +<contact>)`, built from ledger.toml `[acquire]` `agent_token` and `contact` and `[ledger] title`; there is no browser agent and no per-host override. robots.txt is read per host and honoured for the ledger's token and for Claude-User (a 4xx robots.txt allows everything; a 5xx or an unreachable one disallows everything); a Crawl-delay raises the host's gap; a disallowed URL, or a redirect to one, fails the hold with the deciding line in the row and in `<state dir>/robots-refusals.jsonl`. Retries: none for a TLS failure; a 429 or 503 waits its Retry-After (at most 300 s) once, not at all behind a protection page; other 5xx twice. `python3 tools/ledger/acquire/web.py robots <url>` prints the user agent and the verdict. The YouTube adapter (tools/fetch_transcript.py's own requests) and the bulk adapter (tools/stargate_mirror.py's fetch) keep their tools' user agents: the policy binds the web adapter; extending it to them is an open item.

An engine is added by subclassing `database.Engine` (tables, columns, foreign_keys, count, select, query; `q()` quotes an identifier) and registering it in `database.ENGINES` and `connect()`. The adapter only reads; SQLite is opened read-only.

## OCR and rendering by platform (tools/platform-plan.md, Portability)

`python3 tools/ledger/acquire/document.py --detect` (or `ocr.detect()`) is stage 0's report. On macOS the backend is Apple Vision: the binary is found at $LEDGER_OCR_VISION_BIN, ledger.toml `[acquire] ocr_vision_bin`, tools/bin/ocr_vision, <project>/.ledger/bin/ocr_vision or /tmp/ocr, and `python3 tools/ledger/acquire/ocr.py --compile` builds it from tools/ocr_vision.swift into <project>/.ledger/bin/ (the install step). On Linux and Windows the backend is Tesseract (pytesseract, else the binary; $LEDGER_TESSERACT_CMD, $LEDGER_TESSERACT_LANG). Pages are rendered by PyMuPDF, else pdftoppm; with neither, a page that needs OCR is recorded as 'renderer missing' and the hold says so.

Measured on the owner's machine, 2026-10-22 (after handoff 11 of phase 6b): Darwin arm64, Python 3.12.2, pypdf 6.19.0; renderer PyMuPDF 2.0 (pip install pymupdf; pip also installed pymupdf4llm, pymupdf-layout, onnxruntime and flatbuffers as its dependencies); OCR backend Apple Vision, the binary built by `python3 tools/ledger/acquire/ocr.py --compile` at .ledger/bin/ocr_vision (ignored by the repository's allowlist); Tesseract missing; whisper and faster-whisper missing; ffmpeg missing; no GPU. The tests use the built binary through $LEDGER_OCR_VISION_BIN when it is present (tests/_common.py).

## Transcription

Weights come from `--weights`, $LEDGER_WHISPER_WEIGHTS or ledger.toml `[acquire] whisper_weights`, and are never downloaded: openai-whisper loads `<folder>/<model>.pt` by path; faster-whisper opens `<folder>/faster-whisper-<model>/` with local_files_only. CPU by default, CUDA when torch reports one (`--device auto`), MPS only when asked. The README records engine, version, model, weights path, device, language, beam size and (openai-whisper) fp16.

## Tests

```bash
python3 -m unittest discover -s tools/ledger/acquire/tests -t tools/ledger/acquire/tests
```

Every test module blocks sockets for its run (tests/_common.py), so a test that reached the network fails. Tests write only to temporary folders and run on the synthetic casebook corpus (tools/ledger/tests/casebook_corpus.py: notes, transcripts, a held set with PDFs including a paper-capture scan, a canon text with witnesses, held post pairs, built from tools/example-casebook.md in a temporary folder, and one fixture image), so they read no project's held sources and name nothing real; the sample database is built from the corpus's three notes at test time.
