# House schema for structured sections (v1.6, 2026-10-26; v1.5 plus rule (cu) on numbered sub-clauses)

The markdown notes are canonical. `tools/build_db.py` derives `notes.db` (SQLite) from them and never writes back. Every video note keeps its prose sections; the sections below must appear with these exact headings and column headers so the parser can find them. Extra prose before or after a table is fine. Extra columns are not; put extra material in the last column. Timestamps in table cells are always `h:mm:ss` (single-digit hour, `0:05:24`) (a 4-minute mark is `0:04:00`, never `00:04`, which the parser reads as four seconds; tapes under an hour may use `mm:ss` with two-digit minutes, `01:16` not `1:16`). Prose keeps whatever notation the note used. Ranges use `to`: `1:23:31 to 1:28:45`. A claim, person or work the note times nowhere takes `not given`; a speaker present throughout takes `throughout`; a person known from a prose list only takes `name only` in Times as well as Detail.

## 1. Metadata table (top of the note)

Two-column table, keys exactly as below (bold, in the first cell), in this order; the header row may be `| | |` or `| Key | Content |`. Missing keys are allowed only for Host, Guest, Recorded, Description. Retrofits move a misplaced key row into this order without changing its content. Conventions: for a monologue with inserted clips, Host is the narrator and Guest is `none`; a pack's own recording kinds take the pack's conventions ({{pack.channelled_clause}}; the active pack's schema-extensions.md, section 1).

| Key | Content |
|---|---|
| Channel | channel name |
| Host | host name, or `none` |
| Guest | guest name(s); for monologues `none` |
| Speakers | every voice on the recording, comma separated (for tapes with unnamed speakers, the codes) |
| URL | the video URL |
| Uploaded | YYYY-MM-DD |
| Recorded | YYYY-MM-DD, or a bracket with the evidence, or `unknown` |
| Length | `Hh Mm Ss`, seconds from the transcript header; `Hh Mm` when the header gives none |
| Added to notes | YYYY-MM-DD |
| Subjects | links to subject pages |
| Description | the channel description's first substantive paragraph, quoted (skip sponsor, merch and link boilerplate, and say so in the cell if you skipped any) |
| Tags | comma-separated |
| Transcript | link |

## 2. `## Claims ledger`

Every substantive claim by any speaker, in order. Columns exactly:

`| # | Time | Speaker | Topic | Claim | Source class | Move | Note |`

- Topic: one of the pack's closed topic codes, the last of which is `other` ({{pack.topics}}; the active pack's schema-extensions.md, section 2).
- Source class: firsthand, program-record, hearsay, read, inference, host, channelled, clip. The class follows the speaker's declared source, read from the transcript, and must agree with the row's attribution (class audit rule, 2026-09-26): `firsthand` only for what the speaker saw, did or measured; `program-record` only when the chain names a record or a teller inside the program; unit lore stated flat with neither is `host`; `hearsay` when a teller is named or described; `read` when a document, publication or public record is named, AND ALSO when the speaker, whoever they are and in any note, asserts that a document or record exists without naming it ("there is a memo", "records show", "a report concluded"): that row keeps `read`, its attribution says `document claimed, not named: <the speaker's words>` and its chain ends `(document, unnamed)`, because a claimed document is a corroboration target and must stay findable by query; `inference` only when the speaker labels the reasoning as his own; a flat factual assertion with no source and no claimed document is `host`; `channelled` for a relayed voice (the pack's channelled class, {{pack.channelled_clause}}); `clip` for inserted footage. Compound values are normalised to the NON-firsthand class when one part is firsthand (so the attribution requirement still applies to the relayed part), otherwise to the first class, with the original value carried in Note as `Source class as recorded: <value>`. `clip` is an inserted news, promotional or government film; a played clip of a named witness carries that witness's own class with the Speaker column naming them. In a monologue note the narrator's rows are split the same way as anyone else's: hearsay for what unnamed sources told him, read for public record and named documents, inference for reasoning he labels his own, host for unsourced synthesis stated flatly, firsthand for what he says he saw.
- Move: open, partial, closed-outright, closed-subtle, n/a (use n/a for volunteered claims that answer no question in an interview). In a monologue every claim gets a move by the mapping: sourced statement or a stated limit = open, labelled conjecture or inference = partial, unsourced assertion delivered as fact = closed-subtle, a refusal to name or say with a ground given = closed-outright (and a stated decline), a refusal with no ground = closed-subtle with Basis `none stated`. In a monologue note the Claim cell may be a short paraphrase plus `audit N` where the full wording lives in the audit table. A claims row takes the move of its own proposition: a stated limit inside a partial answer is open; a withheld name inside an open answer is partial; the audit row scores the answer as a whole. Where a monologue relays another party's answer to a request, the claims row takes that party's move, as the audit row that cites it does; the narrator's sourcing is carried by the class and chain (readers' rulings, 2026-10-25).
- Note: basis of a closure (a ground from the pack's basis vocabulary, {{pack.basis_vocabulary}}, or none stated), corrections, or the public-record verdict (verified, unverified, contradicted).
- Attribution (chain of custody, from 2026-09-26; ratified after the pilot the same day): for every row whose Source class is not firsthand, the Note cell begins `attribution: <the speaker's declared origin at that point in the recording, verbatim or near-verbatim, quoted where it is a quote, or none stated>; chain: <n>: <Speaker-column voice> <- <hop> <- <hop> (<origin type>).` then the rest of the Note unchanged. Rules: (a) n counts every node including the speaker, so `1: Castellan (unsourced)` is a flat assertion. (b) Origin types: firsthand, program record, document, public record, rumour, unsourced, inference, channelled, basis not stated (an unnamed or anonymous terminal hop whose knowledge the recording never describes), fiction; add `, on tape` when the hop is a played recording. (c) A bare hedge with no teller ("from what I understand") is `none stated`. (d) A speaker voicing what "I was told" by an unnamed institution chains to `<institution> staff (unnamed) (firsthand)`. (e) A monologue's blanket sourcing declaration ("testimony from several CAC engineers", given once) may be cited as the origin of later flat rows, but the attribution must then say `blanket declaration at h:mm:ss` and quote the local cue if any, so the audit can count how many rows rest on the blanket. (f) Inference rows are `1: <speaker> (inference)` with the evidence named in the attribution, unless the speaker cites a specific named source, in which case chain to it. (g) Clip rows chain from the clip's own speaker (the Speaker column), not from the narrator. (h) A row resting on two independent origins carries both chains separated by `; corroboration 2:`. (i) The declared origin must be on the recording; references in the channel description do not count. (j) Do not use `. ` inside the prefix except at its end (write initials without periods and use no ellipses); the chain always ends with the origin parenthetical and a period. (k) A `read` row where the speaker asserts a document exists but does not name it keeps its class and takes `document claimed, not named: <words>; chain: ... (document, unnamed)`; a `read` row with no document even implied is reclassed `host` on the class audit. The audit blurb counts both. (l) A row bundling sub-claims from different origins carries labelled sub-chains: `; <label> 2: ...` (`denial 2:`, `clip 2:`, `corroboration 2:`). (m) A NAMED terminal hop whose basis the recording never describes ("Lisle told me", with no word on how Lisle knew) ends `(basis not stated)`, the same as an unnamed one. (n) Program-record custody is named in the hop: `the record itself, shown on air`; `the record, his memory`; the pack's own custody phrases ({{pack.schema_extensions}}, section 2); `unit history as passed to members` for lore from before the speaker's time; all end `(program record)`. Program-record rows that cite neither a record nor a teller chain `1: <speaker> (unsourced)` and the class should be audited. (o) Hearsay about a named witness with no teller stated chains to the witness `(firsthand)` with `without saying how it reached him` in the attribution. (p) A clip row whose Speaker cell is the host chains from the host to the clip voice `, on tape`; the Speaker cell may be corrected in a later pass. (q) Host rows that are questions or jokes and assert nothing take `attribution: n/a (question); chain: 1: <host> (n/a)` so they do not inflate the unsourced count. (r) A pack clause ({{pack.schema_extensions}}, section 2, rule (r)). (s) Rule (e)'s blanket declaration applies to interviews and hearings too: a witness who states once that he speaks from what others told him (Thale's opening statement to the inquiry at 0:29:33, his *Harbour Talks* "I spoke to about 40 people" at 0:12:50) may be cited as the origin of later flat rows, with `blanket declaration at h:mm:ss` in the attribution. (t) A pseudonymous hop is written `"Heron" (pseudonym)`; a named hop whose basis is never described ends `(basis not stated)` under rule (m), and notes attributed before rule (m) may carry `(unsourced)` for the same case. (u) An inference-classed row that is in fact a flat unsourced assertion keeps `(inference)` on this pass; the class audit is a separate task and the query `source_class='inference' and attribution like 'none stated%'` finds them. (v) A speaker citing his own earlier video or article is `none stated ... (unsourced)`; a self-citation is not an origin. His own observation or priority claim is `1: <speaker> (firsthand)`. (w) A played recording in a middle hop is labelled `inserted clip` in the hop name and the terminal type is left unmodified; `, on tape` is only for a terminal hop. (x) A clip speaker unnamed on the recording but identified in the note takes the note's name with `named by the note` in the attribution. (y) A host's stated limit or vetting statement ("I have not verified this") takes `attribution: stated limit; chain: 1: <host> (stated limit)`. (aa) A chapter-level or section-level declaration ("for this section we reference Thale and Strand") is a blanket for that section only, cited as `blanket declaration at h:mm:ss (section)`. A self-referential blanket ("this timeline is built on my own work") points to no outside origin and its rows stay `none stated ... (unsourced)`. (ab) A quoted institutional self-description with no publication named (a mission statement, a published biography read aloud) takes `<institution> published text (public record)` as the origin. (ac) A row whose Speaker cell is a person relayed by the narrator without a clip chains from that person, with `relayed by <narrator>` in the attribution. (ap) Rule (o) covers named AND anonymous parties: a claim about what an anonymous person said or did with no teller chains to that person `(anonymous) (basis not stated)`; a reported opinion or intent of a named person with no venue chains to the person `(basis not stated)`. (aq) A named person's public remark in a podcast, film, hearing or press is `(public record)`; a book or paper is `(document)`; `author named, work not named` is written as such and ends `(document, unnamed)`. (ar) Sub-chain labels are free text; the parser keeps the whole string. (as) Rule (q)'s n/a form applies to any speaker's joke or rhetorical question, not only the host's. (at) A pack clause ({{pack.channelled_clause}}; {{pack.schema_extensions}}, section 2, rule (at)). (ak) Rows whose Speaker is the channel description chain `1: the channel (description) (unsourced)`. (al) Rule (q)'s n/a form extends to advice, closing reactions, transitions, sound effects and ad copy. (am) Oral tradition as a terminal hop is `(basis not stated)`. (an) On single-node clip chains the type carries `, on tape` (`(firsthand, on tape)`, `(inference, on tape)`); on multi-node clip chains it is dropped. (ao) A host's labelled hunch is `(inference)`; a host's on-set observation is `(firsthand)` and the class audit reclasses it. (ag) A pack clause ({{pack.channelled_clause}}; {{pack.schema_extensions}}, section 2, rule (ag)). (ah) Procedural rows (slates, return counts, sign-offs) take `attribution: n/a (procedural); chain: 1: <speaker> (n/a)` alongside rule (q). (ai) A narrator citing an earlier segment of his own compilation chains `2: <narrator> <- <segment> (firsthand, on tape)`. (aj) A pack clause ({{pack.channelled_clause}}; {{pack.schema_extensions}}, section 2, rule (aj)). (ae) Hop lists join co-sources with `and`, never a semicolon, since `; <label> n:` is the sub-chain separator. (af) A named public figure's public statement used as a terminal hop is `(public record)`; a named hop whose basis is never described is `(basis not stated)`. (ad) The audit-blurb counts required by rules (e) and (k) are added by the class audit pass, not the attribution pass; the queries `attribution like '%blanket declaration%'` and `source_class='read' and attribution like 'none stated%'` supply them. (z) Host rows that are the host's own acts (billing, edit notes, channel history, a phone failing on camera) chain `1: <host> (firsthand)` and are misclassed as host; the class audit query `source_class='host' and chain like '%(firsthand)'` finds them. A sponsor read chains to the sponsor's copy `(unsourced)`. Chains start with the plain speaker name even where the Speaker cell carries a parenthetical. A firsthand row needs neither field. (au) The main chain starts with the Speaker cell; a labelled sub-chain spoken by another voice starts with that voice. A joint Speaker cell ("Ambrose and Castellan") starts the chain as written and is split in a later pass. (av) A researcher's finding is `(document)` when cited as a paper, report or book, `(firsthand)` when the recording describes the researcher's own survey, excavation or measurement, and a vague consensus ("engineers say") ends `(basis not stated)`. (aw) `host` is the class for any flat unsourced row whatever the voice: a guest's unlabelled opinion or value claim, and any speaker's stated limit under rule (y), take `host`; the name is historical. Rules (q), (ah) and (y) rows keep `host`. (ax) Rule (q)'s n/a form extends to exhortations, hypotheticals ("imagine we could") and "is it possible that" questions logged as claims; a joke is written `n/a (joke)`. (ay) A host reacting to an image shown on air is `1: <host> (firsthand)` and firsthand; a host paraphrasing text shown on air chains `2: <host> <- the text shown on air (document)` and is `read`. (az) Where rules (m) and (o) both fit (a named person's own position relayed with no teller), rule (o) governs. (ba) A compound class whose first word is not in the vocabulary ("relayed, firsthand as the hearer") normalises to `hearsay` with `Source class as recorded`. (bb) An inference row whose labelled reasoning rests on a named source stays `inference` and chains to the source (rule f); a row that only cites the source with no reasoning of the speaker's own is `hearsay`, or `read` for a document. A bare hedge ("probably", "I think") counts as a label. A host row chained `(inference)` with no label is rewritten `(unsourced)` on the class audit. (bc) Rule (n)'s custody phrases resolve by what the memory holds: a record the speaker received or reviewed (`unit tasking, his memory`; `the record, his memory`) stays `program-record`; a method he practised himself (`program methodology, his memory as a practitioner`) is `firsthand`; program history from before his time (`unit history as passed to members`) is `host`. (bd) A chain through a named book to outside tellers is `read` when the speaker read their account in the book and `hearsay` when the book is only a pointer and his source was the tellers. (be) A named person's public statement is `read` with `(public record)` when a venue is named or plainly public (press, podcast, hearing, a post online); with no venue it is `hearsay` ending `(basis not stated)` under rule (ap). (bf) A document identified by issuer and date or title ("the Authority's 2018 review of the failure") is named; one identified by issuer or period alone ("Authority documents at the time") is `document claimed, not named`. (bg) `clip` is only inserted promotional, news or government film or an unidentified voice; a played clip of a named witness takes the witness's own class (firsthand, hearsay, inference) with `, on tape` per rule (an), and `clip (firsthand)` compounds resolve to `firsthand`. (bh) A speaker's own reaction or feeling ("I'm angry about it") is `1: <speaker> (firsthand)` and firsthand. (bi) Rule (ad)'s audit-blurb counts are written by `tools/retired/audit_counts.py (retired 2026-10-22; the counts line is generated by tools/note_fill.py)` after the class audit, not by the audit agents; the counts are rows on a blanket declaration and rows claiming an unnamed document (`document claimed, not named`, `author named, work not named`, `publication named, article not named`), which rule (aq)'s form and rule (bt)'s form both feed. (bj) Counting unsourced rows, parse the first chain segment (before the first `; `), since sub-chains may end differently. (bk) A document is claimed when the speaker uses a record word (report, study, paper, publication, poll, data, evidence in writing, the news, records, "you can read", "it is documented"); "shown by experiment", "has been discovered" and textbook science stated flat claim none and are `host`. A chain that already names an unnamed document ("a textbook", "a review article") takes the `document claimed, not named` prefix; author named but work not named stays `read` per rule (aq). (bl) "I've heard" with no teller named or described is a bare hedge under rule (c): `none stated`, class `host`. (bm) A single-class firsthand row whose substance is a relayed statement is reclassed to the relayed part's class with a prefix added; a firsthand row with an incidental relayed detail stays firsthand. (bn) Where a witness has made a blanket declaration (rules (e) and (s)), every later flat program row with no local cue cites the blanket and is `hearsay`; it does not stand as `host (unsourced)`. (bo) Question rows always take rule (q)'s n/a form; a question row carrying another chain is normalised. (bp) A row citing a named person classes by the chain's terminal type: `(public record)` or `(document)` gives `read`; `(firsthand)`, `(inference)`, `(basis not stated)` or `(unsourced)` gives `hearsay`. (bq) A speaker who held or read a program document in an official capacity chains to it `(program record)` and is `program-record` (Harlowe on the Lisle memo, which he read as chief executive); a document that reached him published or leaked is `read` `(document)`. (br) Content a speaker quotes or paraphrases from a document he holds (a memo, an email, a FOIA release, a tape) is `read` chained to the document `(document)`; his owning or obtaining it is a separate firsthand row. (bs) `document claimed, not named` covers a document the claim rests on; a document the claim is merely about, whose content the speaker does not report, is not a source and the row classes by whatever the speaker's basis for saying it exists is. A president's or official's interview clip is a named witness under rule (bg). (bt) A speaker's claim that his own publication exists, with no title given, is `read` with `document claimed, not named` (rule (v) yields, since the paper is a corroboration target); a document no one can produce (a lost paper known by author, year and subject) is likewise `document claimed, not named`. (bu) Rule (bp)'s terminal-type test applies when the speaker consulted the document himself; where the chain reaches a document only through tellers the speaker heard, the class follows the declared immediate source (`hearsay`). (bv) Rule (bo) covers questions that assert nothing; a question that carries a factual premise ("the inspector's three warning signs, right?") classes by the premise's source and keeps its chain. (bw) Rule (bh) covers a speaker's stated feeling about the subject matter; a closing reaction or pleasantry stays under rule (al) as n/a, class `host`. (bx) Advice, exhortation or a closing reaction takes rule (al)'s n/a form even when it rests on another speaker's account given on air; (al) governs over (bp) for rows that assert nothing. (by) Rules (av) and (be) meet as follows: where the recording describes the researcher's own survey or observation the terminal is `(firsthand)` and the class `hearsay`; where only the publication or presentation is cited the terminal is `(document)` or `(public record)` and the class `read`. (bz) "I understand", "as far as I understand" and "I am aware of" are bare hedges (rule (c), class `host`); "I think", "I believe", "probably" and "in my opinion" are inference labels (rule (bb)). (ca) "research", "the work on X" and "the literature" are record words under rule (bk); "engineers who have done more thorough work" describes tellers and is `hearsay` ending `(basis not stated)`. A named analyst's own measurement described on air is `hearsay` ending `(firsthand)`; unnamed researchers' results given in record words are `read` with `document claimed, not named`. (cb) "allegedly", "purportedly", "reportedly", "said to" and "by all accounts" with no teller are none-stated markers (class `host`), not inference labels. (cc) A clip voice unidentified on the recording that relays a named person stays `clip`; the relay survives in the chain. (cd) Rows moved to firsthand on the class audit may keep a prefix ending `1: <speaker> (firsthand)`; a later script strips them, since a firsthand row needs neither field. (ce) Where a document's issuer is also its author: an institutional issuer with no title or date (a Pernell memo, a journal paper by journal only) is `document claimed, not named` under (bf); a personal author with no work named (Strand's books, a Lisle memo) is `author named, work not named` under (aq). (cf) A read row relaying a named witness's public testimony with a venue ends `(public record)` under (be); the witness's own `(firsthand)` terminal belongs to hearsay rows where no venue is given. (cg) A note's probable identification of a clip voice ("probably Harlowe") satisfies rule (x) with `named by the note, probable` in the attribution; a voice the note cannot name is `clip`. (ch) A narrator's on-tape description of a clip speaker's sources may serve as that speaker's blanket declaration, cited `blanket declaration at h:mm:ss (narrator)`. (ci) A host relaying a guest's statement from the host's own earlier published interview is `read` `(public record)` with that interview named; rule (v) covers a speaker citing his own claims, not a guest's words on his channel. (cj) A known text performed or read aloud by a voice other than its author (a novel dramatised on the channel) is `read` `(fiction)`, not `clip`; `clip` stays for inserted news, promotional or government film and unidentified voices. (ck) "Leak" is a record word only when the leak is described as a document or post ("a leaked memo", "the leaked slides"); a leak described as a person's telling is a teller and the row is `hearsay`. (cl) "I'm sure", "it appears", "it seems" and "my sense is" are inference labels alongside rule (bz)'s list; "if X is true" and "what if" are hypotheticals that take the n/a form under (ax) unless the speaker then asserts the consequent. (cm) Rule (bz)'s labels cover reasoning and conjecture; "I think" on hedged recall of a fact or on a value judgement is not a label, and such rows stay `host`. (cn) Where a document reaches the speaker only through tellers ("they have documents"), the row stays `hearsay` under (bu) but carries a labelled sub-chain `; documents 3: ... (document, unnamed)` so the claimed-document query finds it. (co) A public figure saying he read a file is `read` `(document)` under (br) unless the recording says he read it in office, which makes it `program-record`. (cp) A venue named once ("when I interviewed Petra") carries under rules (be) and (ci) for the rest of the same continuous retelling of that person's account, until the speaker turns to another source or topic; rows inside that stretch are `read` `(public record)` with `venue named at h:mm:ss` in the attribution, and rows after the turn revert to hearsay under rule (o). (cq) "I am familiar with", "I have exposure to" and "I have specific knowledge" are bare knowledge claims under rule (bz): `host`, and closed-subtle under the monologue mapping, unless the recording describes the channel; where the speaker has made a blanket declaration on that recording (rule (s)), the blanket governs and the row is `hearsay`. `tools/build_db.py` loads them as `claims.attribution` and `claims.chain`. (cr) A risk, impact or option statement in a document (a modal of possibility such as `could`, `may`, `potentially`, in a risk register, an options list or an impact appendix; owner ruling 2026-10-23, from the pilot's RPM notes) is the author's own statement, class `host`, with move `n/a`: it answers no question and asserts no fact, so the monologue mapping's conjecture = partial does not apply to it and it enters neither the audit's moves nor its counts line; the hedge on such a line is not a label of inference (rule cm). A flat consequence stated as fact in the same document (`must absorb`, `would have a discrepancy`) is an unsourced assertion delivered as fact under the mapping, `host` and `closed-subtle`, unless its reasoning is labelled (rule bb). (cs) A pseudonymous hop is written with its mark and then the terminal type by the usual rules: `"Dr Gee" (pseudonym) (firsthand)`. (ct) A member's flat statement about their organisation's holdings, data or state in their own time, with no word on the recording that they saw, handled or reviewed it, is `host` `1: <speaker> (unsourced)`; `firsthand` is an act of seeing, doing or measuring stated in the passage, never membership alone (2026-10-25). (cu) A rule's or a document's numbered sub-clauses are one claims row where they jointly state one requirement, finding or event, and separate rows where each asserts a distinct obligation, fact, actor or date; the row names the sub-clause numbers it covers in its Time cell (2026-10-26).
- Editor and translator glosses (owner ruling, 2026-09-28): where an editor, translator or compiler (Quayle, Talley, and any later case) states a gloss, correspondence, identification or doctrine without naming where it comes from, the row is that person's: Speaker the editor, class inference or host by the usual rules, chain `1: <editor> (unsourced)`. The same unsourced gloss recurring across several books or notes by one editor is one source, counted once, in cross-checks (Kind agreement, marked "same speaker, not independent"), in timeline Agreement cells, in leads and in the corroboration charts. Talley's own commentary counts as Talley's, never as Quayle's, even inside a reprint of Quayle's edition. Only where the editor says the matter comes from somewhere else (a named manuscript, author, edition or tradition) is the row attributed through that source, with the hop in the chain (`2: <editor> <- <named source> (document)`), and that attribution then needs a verification: a public-record verdict on whether the named source says it, or a lead to check it. The translated text itself keeps its stated chain (for example `Quayle <- the 1888 commissioners' minutes <- the Charter (document)`).

## 3. `## Forthrightness audit`

The forthrightness audit (the form is core, the subject set is the pack's; the name stands by the owner's ruling of 2026-10-22). Every note carries the heading `## Forthrightness audit`, and tools/note_skeleton.py emits it; tools/build_db.py and tools/note_fill.py also accept the one other heading form a draft of the platform plan proposed, so no note needs a change. The audit is mandatory for the subjects the pack names (the audited subjects, {{pack.audited_subjects}}: the active pack's pack.toml `[audit] mandatory_subjects`, read through tools/packload.py); the basis vocabulary and the channelled-class clause are the pack's ({{pack.basis_vocabulary}}, {{pack.channelled_clause}}; the active pack's schema-extensions.md, section 3).

The question-by-question table. Columns exactly:

`| # | Time | Asked by | Question or prompt | Answer summary | Move | Basis | Note |`

Definitions. A **stated limit** ("I have not seen the site and will not pronounce on it") is forthrightness about the edge of one's knowledge: score it open, Basis `n/a`, and note it. A **stated decline** is a refusal to answer, with the ground named by the speaker (a ground from the pack's basis vocabulary, {{pack.basis_vocabulary}}); the ground goes in Basis. Saying "I don't know" is ignorance, not a decline. A refusal with no ground offered is closed-subtle with Basis `none stated`. A **pseudo-decline** is a non-answer with no ground that substitutes another item, dissolves the question, or answers a different one; write `pseudo-decline` in the Note cell. The pack's channelled-class clause ({{pack.channelled_clause}}; the active pack's schema-extensions.md, section 3) says where pseudo-declines are typical and how those inside volunteered monologue are counted. Basis holds `n/a` when nothing is withheld. A prompt that is not on the recording (a question from an earlier session the answer refers to) takes the answer's time and says so in the Question cell.

Followed by one line in this exact form (numbers only):

`Audit counts: open N, partial N, closed-outright N, closed-subtle N, stated declines N, pseudo-declines N.`

Rows with Move `n/a` (definitional rows, questions the host answers himself) are not counted, so the four move counts may total fewer than the rows; the explanatory line says how many. The line is generated from the table by `python3 tools/note_fill.py --note <note> ...` (between `<!-- audit-counts:start -->` and `<!-- audit-counts:end -->`, with the walls, the n/a rows and the basis histogram printed for the explanatory line; `--check` reports a hand line that disagrees; tools/note_fill.md, 2026-10-15); agents do not type it.

One explanatory line may follow the counts line (for instance the mapping used in a monologue or a tape). Then the prose subsections, which must cover: public-record checks, confidence labelling, internal tensions, what is withheld, the host's moves, and what the pack's channelled-class clause adds ({{pack.channelled_clause}}). Their headings and lettering are free-form; retrofits keep the note's existing subsection letters and headings as they are.

- Relation: e.g. colleague, friend, source, named gatekeeper, cited author, host's citation.

## 6. `## Object watch`

`| Time | Object | Witness | Custody | <reference object> criteria met | Strength | Register entry | Note |`

- Custody: contractor, government, private, none, unknown.
- The criteria column (`<reference object> criteria met`; the header line above carries this project's reference object until tools/note_skeleton.py reads the header from the pack): a comma-separated subset of the reference object's criteria ({{pack.reference_objects}}; the active pack's schema-extensions.md, section 6); or `none`.
- Strength: nil, weak, moderate, strong, anti-match, conceptual (a structure inferred from an instrument and never seen is nil with the fact in Note) (a match in function or description with no physical object, e.g. a record describing a core sample that was never taken). Custody of undescribed hardware is nil with the fact in Note.
- Register entry: the number in the pack's object register ({{pack.reference_objects}}), or `candidate`, or `checked N` for an explicit non-hit tested against entry N, or blank.
- A note in which nothing is like the reference object still carries the table: log the nearest physical objects at strength nil with a one-line reason, so they are not later mistaken for claims about it.

Followed by one line, the pack's vocabulary line (`<label>: <word> N, <word> N, ...` over the words and label of {{pack.object_vocabulary}}; the active pack's schema-extensions.md, section 6). Count case-insensitive whole words plus simple plurals over the whole transcript file including the appended channel description (say in the parenthetical if a hit is in the description rather than on the recording). When any count includes false positives (a place name that contains a counted word, a figurative use; a longer word that contains a counted one is excluded by the whole-word rule) a parenthetical after the line saying which is mandatory.

## Parser rules worth knowing

- Unsourced and origin-type counts should parse the first chain segment only (text before the first `; `); `claims.chain` stores the whole string including sub-chains.

- The parser takes the first heading in the file that starts with `## People` (likewise `## Works`, `## Claims ledger`, `## Forthrightness audit`, `## Object watch`, `## Notable quotes`, `## Open questions`, `## Cross-checks`); an older `## People roster` or `## People and works` ahead of the schema section hides it. Retrofits convert the earliest such heading in place.
- The parser reports an Open questions row whose Status does not begin with one of open, checked, closed or superseded.
- Compound moves in older notes ("open on content, closed-outright on identities") take the first class named in Move and keep the full wording in Note.
- Older notes' closed-outright rows with no ground offered keep their class on retrofit, with Basis `none stated`; new notes follow the definition (a groundless refusal is closed-subtle).
- A question the host answers himself before the guest can gets Move `n/a` in the audit too; the counts line then does not sum to the row count and the explanatory line says why.
- A note may keep one trailing note-specific metadata key after Transcript (for instance Scope).
- A hearing: Host is the chair, Guest lists the witnesses, Speakers lists every member.
- A debate: Asked by names the challenger (who may be the other guest); Answer summary records what the challenged party did with it; a one-line note above the table says so.
- Source class for a host recounting his own experience is firsthand with the host in Speaker; `host` is reserved for unsourced synthesis.
- An interview whose note preserves only the guest's claims and none of the host's questions keeps its true Host and Guest and uses the monologue Move mapping, stated under the counts line.
- "Give me another question" is a plain groundless refusal (closed-subtle, `none stated`), not a pseudo-decline: nothing is substituted.
- A decline delivered inside the answer to another question is recorded in that row's Basis cell (Move may stay open); the counts line's stated-declines figure counts refusals, not rows, and the explanatory line says which rows carry more than one.
- "I don't know" that the note itself scored as not answered takes closed-subtle with Basis `not known to him`; ignorance is never a stated decline.
- With two guests, or where the guest questions the host, the answerer is named in the Note cell and a reverse question is marked `<guest> (reverse)` in Asked by.
- A quote item carries one time, one `to` range, or a comma list of times; the parser reads all three.
- A quote the note attaches to two separate occurrences takes the first time in the parenthesis and `repeated at h:mm:ss` in the attribution.
- Length may be corrected on retrofit to the transcript header's seconds; it is the one metadata value a retrofit changes.
- Quote ranges: resolve the start to a transcript paragraph mark; the end may stay at minute precision.
- Old Strength values Loose, Thread and Not applicable map to nil with the wording kept in Note.

## 9. `## Open questions`

`| # | Kind | Asked by | Question | Bears on | What would settle it | Status | Answer | Answered by | Answered on |`

- Asked by (from 2026-09-26): who raised the question, with the same class prefixes as Answered by: `note` (the note's author raised it from the recording; the default for every row written at intake), `video: <speaker, h:mm:ss>` (a speaker poses it on the recording), `own: <who, date>` (the database owner or Claude, in conversation or in a research pass), `page: <link>` (a sweep or research page raised it). A question a speaker poses and the author adopts is `video:`.
- Kind: `question` or `guidance`. Guidance is an instruction to future editors or an observation about a person, place or case, written into the list as if it were a question; it keeps its row here with Status `standing` (it never closes) and is also copied into the Note cell of the entity it concerns wherever that entity already has a row (a register entry, a tracker node, a lead, a speaker ledger's threads, {{pack.speaker_ledgers}}).
- Bears on: the topic code(s) from the 19, comma separated, then a semicolon, then the h:mm:ss time(s) the question arises from; `not given` or `throughout` where the note has none.
- What would settle it: the test or source that would answer it; `unknown` if the note gives none (do not invent one). For a `checked` row this column holds the REMAINING test, replacing the original, so it is always the live next action.
- Status: `open` (no answer yet); `checked` (a partial answer exists in Answer and a statable remaining test is in What would settle it; a partial answer with no statable remaining test is `open` with the finding noted in Answer); `closed` (the substance is answered and nothing remains; a resolved headline with a remainder is `checked`, not `closed`); `standing` (guidance, never closes); `superseded` (promoted to the leads register or another page, with the pointer in Answer).
- Answer: blank while open; otherwise the finding in one or two sentences, with links.
- Answered by: the source of the answer with a class prefix: `note: <link>` for a video in the database; `page: <link>` for a research or subject page; `document: <citation>` for an external document read; `own: <who>, <basis>, <confidence>` for our own research (for instance `own: Claude, general knowledge, unverified`). Never blank when Status is not open.
- Answered on: the date the answer was recorded, YYYY-MM-DD, not the date of the source. Reopen rule (2026-10-01): a later `contradicts` cross-check that cites an answered row (checked or closed) reopens it to `checked`; the earlier Answer stays and gains "Reopened <date>: contradicted by <note> cross-check <n>"; tools/reopen_check.py finds the candidates from notes.db and applies them with --apply. Target check (2026-10-01): integrators write an answer only when the report's question text matches the row's Question or Lead cell (tools/answer_guard.py); refusals go to research/corrections/answer-refusals.md for a hand pass. Roll-up: tools/answers_rollup.py writes research/answered-questions.md, every answered row by date with the answering source.

Retrofit rule: a note's existing open-questions list (usually `## My open questions`) is converted in place: the schema table at the top under this heading, and the original list kept in full beneath under the bold lead-in **The note's original "My open questions" list, kept in full:**. Every item becomes a row with its question sentences verbatim in the Question cell; commentary stays in the original item. Where the original item carries its own partial answer, split it into Answer and What would settle it. A note that recorded no questions carries the empty table and one line, "This note recorded no open questions." The parser takes the first heading starting `## Open questions`.

## 10. `## Cross-checks`

What this note does to the rest of the database: the standing questions and leads it answers, the claims elsewhere it corroborates, contradicts or extends, and the declines elsewhere it fills. Placed directly after `## Open questions`.
**Divergence rule (owner, 2026-09-29).** When two tellers give diverging portions of the same story, the divergence is always recorded, never silently reconciled: a `contradicts` cross-check row (or a timeline row whose Agreement says `contradicts:` or `drifts:`) naming both tellings, and, where the divergence bears on a thread, a leads-register row of kind `divergence` with a test. This applies with particular force when the diverging party is an agency, office, official record or office-holder rather than a private witness: an agency's contradiction of a witness is logged with the agency as the party under suspicion (see the agency ruling of the same date), not as a correction to the witness. The tally of who diverges, on what and how often is generated by `python3 tools/divergences.py` into research/divergence-patterns.md, which is re-run after every intake; it classifies each party's divergences as one instance, topic-specific, or general, so that a party repeatedly used to change a story can be seen.

**Divergence tag (owner, 2026-09-29).** Every `contradicts` cross-check row and every timeline row whose Agreement is `contradicts:` or `drifts:` ends its Note (or Agreement) cell with a machine-readable tag recording the six markers that separate memory error from managed change, so that tools/divergences.py can score them. Form, in square brackets, keys in this order, unknown values as `?`:

`[div: dir=self|other|neutral; core=core|periphery; stab=verbatim|varied|?; indep=yes|no; timing=after-challenge|after-publication|gradual|first|?; path=named|document|withheld|classified|anonymous]`

Optional seventh key, `party=<name>` (added 2026-09-29): when the diverging telling the tag describes is not the note's own speaker (an agency named in an `agency divergence:` prefix, or the other note's teller), name that party so tools/divergences.py credits the row to them rather than to the note's guest. Example: `[div: dir=self; core=core; stab=verbatim; indep=yes; timing=after-challenge; path=classified; party=Vale Water Authority]`.

- `dir`: whom the change serves. `self` if the diverging telling favours the teller or the teller's institution (exculpation, a larger role, a fixed narrative); `other` if it runs against the teller's interest; `neutral` if neither.
- `core`: whether the changed element is the story's core (who, what happened, whether it happened) or its periphery (a date, a number, a minor name, a place detail).
- `stab`: across the teller's own retellings, `verbatim` if the diverging wording repeats word for word, `varied` if the wording differs while the substance holds, `?` if only one retelling is held.
- `indep`: whether the diverging telling is independent of the telling it diverges from (`no` if the same speaker, host, footage, document or a common unnamed source).
- `timing`: what the diverging telling follows: a challenge to the teller (a hearing, an article, a legal exposure), a publication of the other version, gradual drift over time, or `first` when it is the earliest telling held.
- `path`: how the diverging telling's chain ends: a named teller, a document, a stated withholding, a classification claim, or an anonymous source.

The tool classifies each party (and each event) into one of three named classes with a confidence: **honest memory error** (periphery drifts, unsystematic direction, varied wording, independent tellings, gradual timing, named or documentary paths), **deliberate falsehood** (changes that serve the teller, core elements moved, verbatim repetition, changes that follow a challenge, paths that end in a withholding), and **sanctioned disinformation** (the same wording across tellers who are not independent, protected sources, timing that serves an institutional need, and a party that lacks the means to have erred, an agency or office). The tag is the row's reading of two tellings, never a verdict on the teller; the class and its confidence are the pattern across many rows, which is where the method has force: people who appear in several interviews, and events told from several perspectives.


`| # | Kind | This note (time, row, claim) | Elsewhere (note, row) | Verdict | Note |`

- Kind: `answers` (an open or checked `## Open questions` row in another note, or a lead in research/leads-and-inferences.md), `corroborates`, `contradicts`, `extends` (adds to a claim elsewhere without confirming or denying it), `fills` (supplies what a closed-outright or closed-subtle audit row elsewhere withheld). The bare word only.
- This note: the h:mm:ss time, the claims-ledger row number(s) and a short paraphrase or quote, in the form `1:29:59, row 140: ...`.
- Elsewhere: a relative link to the other note or page (short title as the link text, as in Connections), then the row: `claims 209`, `open question 2`, `audit 71`, or for the register `lead 11` after a link to research/leads-and-inferences.md. Several rows may share one cell when they make the same point.
- Verdict: `direct` (states the specific thing), `partial` (states part of it, or a version of it), `same-subject` (speaks to the topic without settling it). The bare word only.
- Note: the chain of custody of the row elsewhere, always: its Source class, its attribution and chain as its own note records them (`custody: hearsay; attribution: Lisle, to him personally; chain: Thale <- Lisle`), so a corroboration by hearsay is never mistaken for one by a firsthand witness, and a retelling of this same speaker is never counted as independent. Then anything else: the direction of a contradiction, whether the answer has been applied to the other note (`applied 2026-09-26`, or `proposed: checked`), whether research/declined-answered-elsewhere.md already pairs a fill.

Rule: the section is filled by the note-writing agent after the note is written and `tools/build_db.py` has run, from the report of `python3 tools/onboard_check.py videos/<note>.md --out <scratch path>`. Every candidate in the report is READ on both sides (the other note's row in its own note, not only the report's excerpt) before it is entered; candidates the agent rejects are not listed. To find a held row elsewhere by its content (a date, a document number, a phrase) use `python3 tools/rows_search.py "<query>" [--note <stem glob>] [--table claims|timeline|audit]`, the full-text search over the row tables (claims, timeline, audit_rows, quotes, mentions; FTS5 table `rows_fts`, rebuilt by build_db.py on every run), which returns the citation `[<stem> claims N]`, `[<stem> tl N]`, `[<stem> audit N]` with the row's cells, before grepping the markdown or reading a note (tools/rows_search.md, 2026-10-15). A term match is never a finding. The table's mechanical cells (This note, Elsewhere, custody from the onboard report) are generated into the section by `python3 tools/note_fill.py --note <note> --onboard wip/<task>/onboard.md [--accept <kept candidates>]` between `<!-- cross-checks:start -->` and `<!-- cross-checks:end -->`, Kind and Verdict left `<!-- fill -->` unless the --accept file gives them; hand rows are kept (tools/note_fill.md, 2026-10-15). Answers the agent is confident of go back to the orchestrator in the reply JSON as `answered_questions` for `tools/integrate_report.py` to apply; the note-writing agent does not edit the other note itself. A note with no cross-checks carries the empty table and one line, "This note's onboarding check found no cross-checks." Older notes acquire the section when a retrofit reaches them; the parser reports the section as missing, and does not count that as a schema gap.

Chain findings (from 2026-09-26). The intake's chain analysis also records patterns in the custody of the note's own claims, as rows of Kind `chain` with Verdict `inference`: a chain that loops back to the same speaker through a document or a second host (a "document" whose wording is the speaker's own; a journalist citing the video that cites him); a circular chain (A cites B who cites A); an excerpt that cuts the passage where the speaker names his basis; a fill of someone else's decline that rests on a blanket declaration or an anonymous terminal hop; two named hops that are one person under two descriptions. The row's Note names the hops and the times, marks the finding as the note's inference, and states the test that would confirm it. Every chain finding is also returned in the reply JSON as a lead (kind `inference`, with sources and the test) for the leads register, so it is tracked with a status. A note with none says so in the section's lead-in line.


**One finding per row: the split rule (owner, 2026-10-01).** A cross-check row carries exactly one Kind, so a comparison that both disagrees and agrees is never filed under one Kind with the other finding buried in the Note cell. It is split: one row per finding, each with its own Kind, Verdict and Note, and each Note cell opening with the point it bears on in the form `point: <date | actor | attribution | substance | mechanism | place | count | custody | wording>` (one word, then anything else). Example: Harlowe on the deferral of the spillway repair against the timeline's Lisle memo row becomes `contradicts` with `point: date` (2016 against 2015) and a second row `extends` with `point: actor` (Harlowe as the one who deferred it, the same speaker repeating himself, which confirms nothing). The `#` cell is permanent in the manner of section 11: a row split after the fact keeps its number for the finding that best matches its original Kind and gives the new finding the next decimal (`12.1`, `12.2`); numbers are never reused or renumbered. A row whose Kind was simply wrong is corrected in place, with `was: <old kind>, corrected <date>` added to its Note cell.

**Settlement after a correction (owner, 2026-10-01).** When a claim is corrected (section 4's `Corrected <date>` note) the cross-check rows elsewhere that cite the old wording are not deleted and keep their Kind, because the divergence was real when recorded. Each such row gets `settled <date>: the checked claim was corrected to <gist>; <what remains of the finding, or 'nothing remains'>` prepended to its Note cell, after the point marker if one is present, so a reader and the map can tell a live disagreement from a resolved one. tools/build_db.py exposes both markers (point, settled) from the Note cell.

**Rulings from the stage-one sample (owner and assistant, 2026-10-01).** (a) Independence decides `corroborates`: a same-speaker repeat, or a relay agreeing with its own source, is `extends`, never `corroborates`. (b) Two disagreements on different points are two rows, one per point. (c) Settlement applies to any Kind, not only `contradicts`. (d) When a correction changes only the custody, attribution or the availability of a test, and the finding itself stands, the row gets `revised <date>: <what changed>` instead of `settled`, and the stale custody line may be refreshed in place with the old wording kept after `was:`. (e) The same markers apply when the corrected claim is on this note's side (the This cell). (f) Point vocabulary: `date`, `actor` (who did it), `credit` (who is credited with doing or finding it), `attribution` (who is said to have said it), `source` (a relay misreporting what its source said), `substance`, `mechanism`, `place`, `count`, `custody`, `wording`. (g) A Note cell that says `Proposed: ... (not applied)` gets `applied <date>` appended once the proposal has in fact been applied, and the proposal text stays.


**Rulings from stage one of the audit (2026-10-01, ten batches).** (h) Settled against live: a correction that fixes the database's own reading (a misdescribed clip, a wrong venue in a chain, a wrong class, a mistaken verdict) settles the row; a correction that only annotates a teller's own error leaves the divergence live, and the row stays with a point marker. (i) `adopted <date>`: when the other note's correction merely writes this row's own finding into its record (it now notes the divergence, cut or misattribution) and the tellings stand, the row gets `adopted <date>` rather than settled or revised. (j) `applied <date>` covers every wording of a proposal, not only "(not applied)", once the proposal is verified in the target. (k) Two relays of one common source, or two texts that may descend from one tradition, are `extends` unless the row shows the routes independent; a row with several Elsewhere targets keeps `corroborates` for the targets that are independent and names the dependent one in the Note. (l) An identification row (a clip shown to be the same recording as another) is `extends` with `point: identity`. (m) A stale custody line may be refreshed in any marked row (settled, revised, adopted), old wording after `was:`. (n) The settlement, revised and adopted markers apply to `extends`, `answers` and `chain` rows whose finding a correction narrows, confirms or adopts. (o) Point vocabulary adds `identity`, `title` (a person's post or rank) and `size`. (p) `party=` is required in the tag whenever the diverging teller is not the note's own speaker (a host, a relay, an office); older rows missing it are a note-level pass of their own. (q) The markers precede the `agency divergence:` prefix, and tools/divergences.py skips them. (r) Rows a split both relabels and splits keep the original number for the relabelled finding. (s) A trivial slip (an interviewer's wrong month for a hearing) is still recorded under the divergence rule; the tag's `core=periphery` carries its weight.

## 11. `## Dated timeline`

Every date or datable event the speaker states, one row each, in chronological order, placed before `## Open questions` (added 2026-09-27; the owner's timeline of events is moments in time, not upload dates). Each dated event is also its own claims-ledger row with the date in the claim text.

**Row IDs are permanent decimal IDs (owner ruling, 2026-09-28).** The `#` cell is an ID, not a position, in the manner of the Dewey decimal system: IDs increase down the table, never change and are never reused, so a citation such as "tl 12" stays valid forever. A new row goes into its chronological place with an ID between its neighbours' IDs: between 12 and 13 it is 12.1 (then 12.2 ...); between 12 and 12.1 it is 12.01; between 12.1 and 12.2 it is 12.15; after the last row it takes the next whole number. Never renumber. Insert with `python3 tools/timeline_insert.py <note.md> <rows.json>` (it computes the place and the ID, and ignores legacy rows that were appended out of order). A legacy out-of-order row may be moved into place with a new decimal ID only if nothing outside the note cites its old ID; its Agreement cell then ends "(was tl N until 2026-09-28)". The parser stores the ID as text (`timeline.n`) and its numeric value (`timeline.n_sort`).

`| # | Date (as stated) | Sortable | Event | Speaker, basis (time) | Chain | Database link | Agreement |`

- Date (as stated): the speaker's words ("the late 50s", "in 1993", "two weeks after the minister's visit").
- Sortable: an ISO-style anchor for sorting: `YYYY`, `YYYY-MM` or `YYYY-MM-DD`; prefix `~` when approximate or inferred by the note; a range as `YYYY..YYYY` (the parser sorts on the first year); years BC as negatives (`~-10000` for about 12,000 years ago); `?` when the recording gives no anchor. Never invent precision.
- Event: what happened, one clause, with the actors.
- Speaker, basis (time): who states it, on what basis (firsthand, a named document, hearsay from whom), and the h:mm:ss.
- Chain: the chain of custody, as in the claims ledger.
- Database link: the note and row already holding the same event (the note's short label as a relative link, then `claims N`), or `new`.
- Agreement: `matches`, `drifts: <how>`, `contradicts: <what the other source says>`, or `new`, against the date the database already holds for the event. The first word is parsed (`timeline.agreement_kind`). The agent rules it from `wip/<task>/timeline-candidates.md`, the date-keyed list of held rows on or near every date the source carries, written by `python3 tools/timeline_prepass.py <units> --wip wip/<task>` (tools/timeline_prepass.md, 2026-10-15), and searches beyond it only for a date it marks as having no held row.

`tools/build_db.py` loads the section as `timeline` (with `sort_key` for ordering and `approx` for the `~` prefix). The master and consolidated timelines under research/ are built from this table; contradictions become leads.
